# Caravaggio Web Development Work Plan

Project phases, milestones and assessment deadlines (October 2026–January 2027).

Planning baseline supplied by Alessandro Benevelli on 25 October 2026. These are planned activities and target dates, not a statement that the activities have been completed.

The assessment deadlines agree with the official syllabus supplied by the author. See [course-requirements.md](course-requirements.md) for the course context, assessment weighting and Contribution Statement deadlines.

| Dates | Phase and planned activities |
| --- | --- |
| **1–7 October 2026** | Ideation: define the concept, audience and scope; research Caravaggio’s works and develop the Light, Shadow and Blood structure. |
| **8–20 October** | Prototyping: create the Figma layouts, select artworks and details, and develop navigation, anecdotes, helpers and language selection. |
| **21–25 October** | Refine and test the prototype and prepare the submission. Ready by 25 October, two days before the Assessment 1 deadline on 27 October. |
| **28 October–8 November** | Begin website development: set up the development environment and local web server; build the HTML structure, CSS and responsive layouts. |
| **9–15 November** | Add JavaScript interactions, scroll snapping, language selection, helpers and video/audio controls. Deliver the first interactive version by 15 November. |
| **16–22 November** | Configure AWS hosting using Amazon S3 and CloudFront, enable HTTPS and deploy the first working version. Verify asset loading, navigation and media delivery. |
| **23–27 November** | Perform functional testing and an initial browser compatibility assessment. Check keyboard navigation, helpers, translations, scrolling, media playback and different screen sizes. |
| **28–29 November** | Fix defects, retest and complete documentation. Working version ready by 29 November, two days before the Assessment 2 deadline on 1 December, 11:59 p.m. |
| **30 November–1 December** | Reserve time for unexpected corrections, verify the live website and submit Assessment 2. |
| **2–8 December** | Conduct user testing and assess desktop, tablet and mobile compatibility. Design the digital guestbook interface, the Amazon DynamoDB database structure and the content policy. |
| **9–15 December** | Implement the guestbook, allowing visitors to leave a message and signature as in a museum or gallery. Use AWS Lambda and API Gateway for the backend, Amazon DynamoDB for storage, and Amazon Nova through Amazon Bedrock to assess submissions against the content policy before publication. Add server-side input validation, submission limits and safe handling of database operations. |
| **16–20 December** | Test guestbook submissions, moderation decisions, service failures and security controls. Check that messages are displayed safely as plain text and that unreviewed submissions remain unpublished if moderation is unavailable. Resolve usability and compatibility issues. |
| **21 December–3 January 2027** | Complete regression testing, accessibility and performance checks, content review, documentation and backups. Final version ready by 3 January, two days before the Assessment 3 deadline on 5 January, 11:59 p.m. |
| **4–5 January** | Keep a final buffer for unexpected corrections, verify the deployed release and submit Assessment 3. |
